# VHS-Sat-Lite

Локальный мультимедийный сервер для Windows: превращает папки с видео,
IPTV-плейлисты и камеры в HLS-потоки и multicast UDP. Управление — через
веб-интерфейс на `http://localhost:8300`, просмотр — на `http://localhost:8301`.

## Возможности

- **Каналы из папок** — ротация видеофайлов по расписанию (random / mtime / name).
- **IPTV-каналы** — ретрансляция плейлиста провайдера (M3U), импорт массовый.
- **Камеры** — RTSP/HTTP-потоки, перекодирование для браузеров.
- **Мозаика** — до 9 камер в одной сетке (без DVB).
- **Выходы** — HLS (браузер, мобильные, Android TV), multicast UDP (VLC, Kodi, приставки).
- **EPG** — расписание для каналов из папок.
- **Оверлеи** — бегущая строка и Picture-in-Picture поверх потока.
- **Расписания оверлеев** — включение/смена по времени и дням недели.

## Требования

- **Windows 10/11** (проект собран под Windows, Linux не тестировался).
- **Python 3.11+** (проверено на 3.12).
- **FFmpeg** — `ffmpeg.exe` и `ffprobe.exe` должны лежать в `bin\` рядом с `server.py`.
  Скачать: https://www.gyan.dev/ffmpeg/builds/ → `ffmpeg-release-essentials.zip`.
  Скопировать только `ffmpeg.exe` и `ffprobe.exe` в `VHS-Sat-Lite\bin\`.
- **Порты 8300 (админка) и 8301 (viewer)** должны быть свободны. При необходимости
  открыть в брандмауэре Windows.

## Установка

1. Скопировать проект в папку **без пробелов в пути** (например `C:\VHS-Sat-Lite`).
2. Создать виртуальное окружение:
3. python -m venv .venv 
4. .venv\Scripts\activate 
5. pip install -r requirements.txt 
6. Положить `ffmpeg.exe` и `ffprobe.exe` в `bin\`. 
7. Запустить - python server.py
8. Открыть `http://localhost:8300`. При первом запуске — форма создания
администратора (пароль ≥ 6 символов). 
9. После входа — создать каналы через кнопку **«➕ Создать канал»**.

## Каналы

### Канал из папки

Источник — локальная папка с видеофайлами (`.mp4`, `.mkv`, `.avi`, `.ts`, `.mov`,
`.m4v`, `.webm`). Файлы проигрываются по кругу, порядок — по настройке «Ротация»:

- `random` — случайный (перемешивание при старте);
- `mtime_asc` / `mtime_desc` — по дате изменения;
- `name` — по имени A→Z.

Опция «Перемешивать при каждом цикле» — `reshuffle_on_loop` — включает
пересборку плейлиста по завершении цикла.

### IPTV-канал

Источник — URL провайдера (`http://`, `https://`, `rtsp://`, `rtmp://`,
`udp://`, `rtp://`). Поддерживается импорт M3U: `/channels/iptv/import`.
Можно загрузить файл или указать URL, разобрать, выбрать нужные каналы и
создать пачкой.

**Важно:** для каналов с битыми DTS провайдера (`Non-monotonic DTS`)
используется принудительное перекодирование (`-fflags +genpts
-avoid_negative_ts make_zero` + `libx264`). Это увеличивает нагрузку на CPU,
но делает поток совместимым с браузерным HLS.js. Стратегия задаётся полем
`codec_strategy`: `auto` (для IPTV = encode), `copy` (без перекодирования),
`copy_video` (видео как есть, звук → AAC), `encode` (полное перекодирование).

### Камера

То же, что IPTV, но `codec_strategy=auto` выбирает `encode` (камеры часто
отдают H.265/G.711, которые браузеры не поддерживают).

### Мозаика

До 9 источников (RTSP/HTTP) в сетке 3×3 или меньше. Порядок камер =
порядок ячеек (слева-направо, сверху-вниз). Названия показываются в углу
каждой ячейки.

## Оверлеи

Доступны на отдельной странице `/channels/<id>/overlays` (кнопка 🎬 в списке каналов).

### Бегущая строка (ticker)

Можно создать **несколько** именованных бегущих строк. У каждой — свой текст,
скорость, размер шрифта, цвет, фон. Одна из них может быть «по умолчанию» —
показывается, когда нет активного ticker-расписания.

**Реализация:** текст пишется в `data/ticker/<channel_id>.txt`, FFmpeg
использует `drawtext=textfile=...:reload=1`. Это позволяет **менять текст
без перезапуска канала** — достаточно записать новый текст в файл, FFmpeg
подхватит его на следующем кадре.

**Ограничение:** скорость, цвет и размер шрифта **не перечитываются на лету** —
их изменение вступит в силу только при следующем перезапуске канала.

### Picture-in-Picture (PiP)

Статичная картинка в углу потока. Позиция — один из четырёх углов, отступ и
ширина настраиваются. Файл загружается через форму (PNG или JPEG, ≤ 5 МБ),
сохраняется как `data/pip/<channel_id>.png`.

**Реализация:** FFmpeg `overlay` с `scale=W:-1`. Основной поток нормализуется
через `scale=iw*sar:ih,setsar=1` — это исправляет растяжение PiP на анаморфных
PAL-потоках (720×576 SAR 64:45 → 1024×576 SAR 1:1).

**Ограничение:** PiP включён — значит, поток **перекодируется** (libx264).
`-c copy` невозможен, потому что `overlay` требует декодирования и
перекодирования. Нагрузка на CPU выше, чем у `copy`.

### Расписания оверлеев

**Ticker-расписания** — переключают бегущую строку по времени и дням недели:

- Формат времени: `HH:MM`.
- `start_time == end_time` — весь день.
- Окно через полночь (например `22:00–06:00`) поддерживается.
- Дни недели: 1=Пн … 7=Вс (чекбоксы).
- `priority` — при пересечении побеждает большее значение.
- **Пересечение ticker-расписаний запрещено** — при попытке создать
  будет ошибка с указанием конфликтующего расписания. Если нужно
  приоритетное — выключите старое через `✓`/`✗`.

**Как работает:** scheduler раз в 30 секунд определяет активное ticker-расписание
(или дефолт) и перезаписывает `data/ticker/<id>.txt`. FFmpeg с `reload=1`
подхватывает — **без разрыва HLS**.

**PiP-расписания** — позволяют задать картинку для конкретного временного окна.

- Картинка загружается через 📤 в строке таблицы, сохраняется как
  `data/pip/<channel_id>_<schedule_id>.png`.
- При удалении расписания файл картинки тоже удаляется.
- **Ограничение (временно):** PiP-расписания **создаются и хранят картинку**,
  но **на поток пока не влияют**. `overlays.py` использует только дефолтный
  PiP из `channels`. Автоматическая смена PiP по расписанию запланирована
  на шаг 7.4 (два процесса FFmpeg на канал, разрыв HLS 5–10 секунд при смене).

## Известные ограничения

### Общие

- **Windows-only.** Linux не тестировался. `bin\ffmpeg.exe` — Windows-сборка.
- **Пути без пробелов.** `C:\Program Files\VHS-Sat-Lite` может ломать
  экранирование в `-filter_complex`. Используйте `C:\VHS-Sat-Lite`.
- **Порты 8300/8301** должны быть свободны. При занятом порте — ошибка
  `[WinError 10048]`.

### Оверлеи

- **Ticker → только текст на лету.** Скорость, цвет, размер, фон — при
  следующем перезапуске.
- **PiP → перекодирование.** Если канал был `-c copy`, при включении PiP
  он станет `libx264`. Нагрузка на CPU растёт, особенно на нескольких
  каналах одновременно.
- **PiP-расписания пока не влияют на поток** (см. выше). В UI создаются, но
  на эфир не действуют.
- **PiP-расписание → разрыв HLS 5–10 сек при смене** (когда 7.4 будет
  реализован). Зритель переподключается к новому плейлисту. Ticker таких
  разрывов не даёт.

### Сеть

- **VPN блокирует локальный IPTV.** Приватные адреса провайдера
  (например `10.24.0.151`) доступны только из локальной сети. Если
  включён VPN, запросы уходят в туннель, и поток не играет —
  `Error reading HTTP response: End of file`. Решение: выключить VPN
  или настроить split tunneling / исключение для подсети `10.0.0.0/8`.
- **Multicast UDP** — работает в локальной сети, но многие провайдеры и
  роутеры блокируют multicast. Используйте HLS, если зрители не в одной
  подсети с сервером.

### База данных

- SQLite с `PRAGMA foreign_keys = ON` и `ON DELETE CASCADE`.
- **Не редактируйте `data/vhs-sat.db` руками при работающем сервере** —
  возможна блокировка. Остановите сервер, сделайте бэкап, потом правьте.
- Схема мигрируется автоматически при старте (`init_db()` → `_migrate()`).
  При обновлении проекта — просто перезапустите сервер.

## Автозапуск каналов

При старте сервера каналы, которые были запущены до остановки, **автоматически
запускаются** через 3 секунды (поток `_autostart` в `main()`). Статус хранится
в таблице `channel_state.running`.

При нажатии «Стоп» в админке статус `running` сбрасывается в 0 — такой канал
не будет автозапущен. При Ctrl+C сервера статус **сохраняется** (`_shutdown`
флаг в `ChannelRunner`).

## Журнал событий

`/events` в админке — просмотр `logs/events.jsonl` (JSON Lines).
Уровень (`info` / `warn` / `error`) настраивается на странице `/settings`.

## Просмотр (Viewer)

Порт **8301** — отдельное Flask-приложение:

- `/` — список запущенных каналов с превью.
- `/watch/<id>` — плеер HLS.js.
- `/playlist.m3u` — M3U-плейлист запущенных каналов (для VLC/Kodi/TiviMate).
  Поддерживает `?format=multicast`, `?type=camera`, `?token=...`.
- `/download` — страница загрузки APK для Android TV (файл в `downloads/`).

Viewer по умолчанию **публичный** (для домашней сети). Если нужна
аутентификация — `viewer.public: false` в конфиге, тогда редирект на админку.
