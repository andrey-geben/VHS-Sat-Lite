⚠ Важно про PiP и расписания

Бегущая строка с расписанием меняется без разрыва HLS — FFmpeg перечитывает текстовый файл (задержка ≤ 30 секунд).

PiP-картинка с расписанием требует двух процессов FFmpeg на канал. Нагрузка на CPU практически та же, но +50–100 МБ RAM и разрыв HLS 5–10 секунд при смене картинки по расписанию.

Расписания PiP, добавленные после старта канала, вступят в силу только после перезапуска. Ticker-расписания — без перезапуска.

Расписания

Расписания переопределяют дефолтные настройки на своё время. start_time == end_time — весь день. Окно через полночь (например 22:00–06:00) поддерживается. Пересечение ticker-расписаний запрещено — при попытке создать будет ошибка.

Для pip_image-расписаний картинка загружается через 📤 в строке таблицы. Сохраняется как data/pip/<channel_id>_<schedule_id>.png. При удалении расписания картинка тоже удаляется.
